# 카톡 자체 DB 안 읽음 검사

별도 앱 `TalkSignalUnreadCheck.app`으로 카카오톡의 로컬 SQLCipher DB에서 채팅방 이름과 `countOfNewMessage`를 조회합니다. 기존 TalkSignal 메뉴바 앱 및 macOS 알림 DB 검사 앱과 별개입니다. 실제 설치 버전의 호환성과 모바일 읽음 동기화는 현장 검증이 필요합니다.

## 접근 범위

- DB는 `SQLITE_OPEN_READONLY` 및 `query_only`로 엽니다. 읽을 수 없거나 쿼리가 실패하면 0개로 표시하지 않습니다.
- 실제 데이터 SELECT는 채팅방 이름, 안 읽은 수, 1:1 상대의 표시 이름 조회에 필요한 필드로 제한합니다. SQLite authorizer가 메시지 테이블 조회, 쓰기, ATTACH 및 확장 함수 호출을 차단합니다.
- 메시지 본문 조회·전송, 외부 서버 호출, 카톡 창 조작, 읽음 처리 기능이 없습니다.
- DB 접근에 필요한 장치/계정 식별값은 카톡 설정 및 시스템 정보에서 메모리로 읽습니다. 파생 키와 식별값은 로그, 파일, 프로세스 인자에 남기지 않습니다. 계정 식별값 확인이 오래 걸리면 제한된 시간 단위로 탐색하고 자동으로 중지합니다.
- 복수 계정이나 같은 이름의 여러 방은 임의로 합치지 않고 불확실 상태를 표시합니다.
- 로컬 결과와 상태 변화 기록에는 지정한 채팅방 이름, 안 읽은 수, 시각 및 진단 메타데이터만 기록하며 파일 권한은 0600입니다. 대화 기록/계정 식별값/키를 출력하지 않습니다. 보고서는 Git에 올리지 마세요.
- UI가 닫혀도 검사가 계속됩니다. 중지는 앱의 **검사 종료** 버튼으로 합니다.

## 빌드와 테스트

Homebrew의 `sqlcipher` 라이브러리가 필요합니다. 현재 빌드 스크립트는 이 Mac의 Homebrew 경로에 연결하므로 다른 Mac으로 배포하는 패키지가 아닙니다. 종속 라이브러리의 OS 요구 사항을 맞추기 위해 현재 Mac의 OS 주 버전을 최소 요구 버전으로 사용합니다.

```sh
bash scripts/build-unread-check.sh '검사할 채팅방 이름'
```

빌드 후 자체 테스트가 가짜 메모리 DB에서 단체방/1:1 이름, 2→0 변화, NULL/중복/누락 처리를 확인합니다. 별도로 메시지 조회, DB 수정, ATTACH, 확장 로딩 거부를 확인합니다. 이 테스트는 개인 카톡 DB를 열지 않습니다.

실제 검사에는 **TalkSignal Unread Check**에 전체 디스크 접근 권한을 부여해야 합니다. 이 OS 권한은 카톡에 한정되지 않습니다. 임시 서명 앱을 재빌드하면 기존 권한이 적용되지 않아 재등록이 필요할 수 있습니다.

## 참고 코드

DB 경로/키 파생 방식과 조회 필드는 `silver-flight-group/kakaocli`의 커밋 `8b6ffcfdaebc592a735dc1a8bd5e50037e626406`을 검토하여 참고했습니다. 키 파생 코드는 MIT 허가로 재사용했으며 `../../Sources/Database/THIRD_PARTY_LICENSE.txt`를 포함합니다. 원본 도구의 전송/본문 조회/네트워크/로그인 자동화 기능은 포함하지 않습니다.

이 코드는 카카오의 공개 API가 아니므로 앱 업데이트로 구조나 암호화 방식이 변경될 수 있습니다. 로컬 DB의 값이 서버/모바일과 동기화되는 시점은 별도로 확인해야 합니다.

## 로컬 검증 진행 상황 (2026-10-23)

- 실제 카톡 DB를 읽기 전용으로 여는 데 성공했습니다. 현재 DB의 `NTChatRoom.countOfNewMessage` 필드가 존재합니다.
- 지정한 1:1 상대의 이름이 유일한 채팅방과 일치하며, 현재 안 읽은 수 0개가 조회됐습니다.
- 이때 카톡 AX 창은 0개였고 알림 센터 AX 창은 위젯 3개뿐이었습니다. 검사 도중 카톡 창이나 알림 센터 패널을 열지 않았습니다.
- 새 메시지 수신 전 0개 → 사용자가 수신 후 읽지 않았다고 확인했을 때 1개 → 휴대폰에서 읽었다고 확인한 뒤 0개로 바뀌는 것을 실제 검증했습니다. 세 단계 모두 카톡 창과 알림 센터 패널을 열지 않았습니다. 카톡 프로세스는 실행 중이었습니다.
- 이 결과는 현재 Mac/카톡 버전과 테스트한 1:1 방에서의 검증입니다. 앱 종료, 로그아웃, 오프라인, 다른 버전에서의 동작을 보장하지 않습니다. 기존 메뉴바 앱의 감지 방식은 아직 변경하지 않았습니다.
- 테스트한 단체방의 사용자 지정 표시 이름은 현재 쿼리로 일치하지 않았습니다. 단체방 이름 처리의 추가 확인이 필요하며, 이 단계에서는 1:1 방을 대상으로 합니다.

공유 리더·키 파생·C 탐색 소스는 `Sources/Database/`에 있습니다. 이 진단 앱과 메인 메뉴바 앱이 같은 구현을 빌드합니다.
