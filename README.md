# TalkSignal

지정한 카카오톡 채팅방에 안 읽은 메시지가 있으면 macOS 메뉴바에 표시하는 개인용 앱입니다. 0.2부터 카카오톡 자체 로컬 DB의 안 읽은 수를 읽습니다. 카톡이 실행 중이라면 **카톡 창과 알림 센터를 모두 닫아도** 조회할 수 있습니다.

## 사용 방법

1. `build/TalkSignal.app`을 실행하고 메뉴바 아이콘 → **설정…**을 엽니다.
2. 감지할 이름을 띄어쓰기·이모지까지 입력하고 아이콘과 숫자 표시 여부를 선택합니다. **저장하고 적용**을 누릅니다.
3. **시스템 설정 → 개인정보 보호 및 보안 → 전체 디스크 접근**에서 **TalkSignal**을 허용합니다. 목록에 없으면 `+`로 이 앱을 추가합니다. macOS 안내가 나오면 **종료 및 다시 열기**를 누릅니다. 진단용 Unread Check의 권한과는 별개입니다.
4. 카카오톡은 로그인한 채 실행해 둡니다. 빨간 버튼으로 창을 닫아도 됩니다. 앱 자체를 종료하면 감지할 수 없습니다.

| 표시 | 의미 |
| --- | --- |
| 선택한 아이콘 + 분홍색 점 및 선택적 숫자 | 지정한 채팅방에 안 읽은 메시지가 있음 |
| 선택한 아이콘만 표시, 상태가 ‘안 읽은 메시지가 없어요’ | 조회 성공, 안 읽은 수 0 |
| 선택한 아이콘 + 주황색 점 | 권한 부족, 카톡 종료, 이름 미발견·중복, DB 조회 실패 등 |

폰에서 읽은 상태가 Mac의 카톡 DB에 동기화되면 다음 조회에서 분홍색 점과 숫자가 꺼집니다. 기본 아이콘은 설정 메뉴를 열 수 있도록 남습니다. 기본 조회 간격은 3초이며 네트워크 동기화·절전·첫 실행 준비 시간에 따라 반영이 늦어질 수 있습니다. 준비 중에는 메뉴에 진행 상태를 표시합니다.

**지금 확인**은 즉시 다시 조회하고 중단된 계정 탐색을 재시도합니다. **알림 표시 미리보기**는 4초간 분홍색 점의 모양만 보여 주며 실제 메시지나 읽음 상태를 변경하지 않습니다.

## 권한과 개인정보

**요구하는 macOS 권한은 실제로 ‘전체 디스크 접근’입니다. 카톡 폴더만 허용하는 권한이 아닙니다.** 아래의 접근 범위는 현재 앱 코드의 동작이며, macOS가 카톡 폴더만 접근하도록 제한해 주는 샌드박스는 아닙니다.

- 카톡 컨테이너의 로컬 DB와 카톡 설정 파일, 이 Mac의 기기 식별값을 사용합니다. 다른 문서·사진·메일을 탐색하는 기능은 없습니다.
- DB는 `SQLITE_OPEN_READONLY`와 `query_only`로 엽니다. 고정 SELECT의 읽기 허용 목록은 `NTChatRoom`의 이름·안 읽은 수·상대 연결 ID와 `NTUser`의 이름·이름 연결용 열입니다. 메시지 테이블, 본문, 첨부파일 조회 및 DB 변경을 허용하지 않습니다.
- 채팅방 이름과 안 읽은 수를 조회해 지정한 이름과 정확히 일치하는 방 하나를 선택합니다. 동일 이름이 여러 개거나 값이 잘못되면 0으로 간주하지 않습니다.
- 첫 실행 시 로컬 계정 식별값을 확인하고 DB 키를 메모리에서 계산합니다. 필요하면 제한된 범위에서 로컬 해시 비교를 수행하므로 처음 수십 초간 CPU 사용량이 늘 수 있습니다. 탐색은 회당 90초, 최대 3회로 제한합니다. 키·계정 식별값을 파일이나 명령행 인자로 저장하지 않습니다.
- 감지 이름·아이콘·숫자 표시 설정만 UserDefaults에 저장합니다. 메인 앱은 메시지 본문이나 수신 기록을 저장하지 않으며 네트워크 요청·분석 SDK·외부 전송 기능이 없습니다. 별도 진단 앱의 보고서는 메인 앱에 포함하지 않습니다.
- 카카오톡을 열거나 클릭해 읽음 처리하지 않습니다. 손쉬운 사용 권한은 새 감지 방식에 필요하지 않습니다.

## 자동 실행과 제약

- 이 Mac의 기존 **로그인 시 열기** 등록과 앱 경로를 유지하도록 업데이트합니다. 다른 Mac에서는 **시스템 설정 → 일반 → 로그인 항목 및 확장 프로그램**에 앱을 추가하세요. 카카오톡도 실행·로그인되어 있어야 합니다.
- 비공식 DB 구조를 이용합니다. 카카오톡 업데이트나 계정 변경에 따라 동작하지 않을 수 있습니다. 실행 PID·계정 표식이 바뀌면 캐시를 버립니다. 여러 계정이 감지되면 추측해서 표시하지 않습니다. 로그아웃·다중 계정 전환의 실제 검증은 아직 하지 않았습니다.
- 현재 검증한 대상은 1:1 채팅입니다. 카톡 UI의 단체방 이름과 DB 이름이 다른 경우 찾지 못할 수 있습니다. 단체방 사용자 지정 이름은 지원을 보장하지 않습니다.
- 절전·로그아웃 중 실시간 감지는 불가능합니다. 폰의 읽음 상태를 Mac의 카톡이 아직 동기화하지 않았다면 잠시 기존 숫자가 남을 수 있습니다.
- 공식 Kakao API가 아니며 Kakao와 무관한 개인 프로젝트입니다. Developer ID 서명·공증 없이 로컬 ad-hoc 서명합니다. 재빌드하면 전체 디스크 접근 권한을 다시 등록해야 할 수 있습니다.

## 빌드와 테스트

현재 빌드는 Apple Silicon macOS 27 이상, Xcode Command Line Tools, Homebrew `sqlcipher` 및 `openssl@4`를 사용합니다. SQLCipher와 libcrypto를 앱 안에 복사하므로 배포 앱은 Homebrew의 라이브러리 경로에 의존하지 않습니다. 관련 라이선스도 앱 리소스에 포함합니다.

```sh
./scripts/test.sh
./scripts/build.sh
```

빌드 결과는 `build/staging/TalkSignal.app`입니다. 실행 중인 TalkSignal을 종료한 다음 기존 `build/TalkSignal.app`을 백업하고 결과를 그 경로로 복사합니다. 기존 설정·로그인 항목을 유지하려면 앱 경로와 번들 ID를 바꾸지 마세요. 테스트는 가상 DB를 사용하며 실제 카톡 DB를 수정하지 않습니다.

## 구조

- `Sources/App.swift`: 메뉴바·설정·조회 스케줄
- `Sources/ChatReader.swift`: 실행 상태·조회 오류·중복 이름 처리
- `Sources/Database/`: 공유 읽기 전용 DB 리더와 메모리 내 키 계산
- `Tests/CoreTests.swift`, `Diagnostics/Unread/SelfTests.swift`: 이름·표시 상태·SQL 접근 제한 검사
- `Diagnostics/`: 별도 실험용 앱. 메인 앱은 알림 센터 DB나 접근성 기반 감지를 사용하지 않음

개인 이름이나 메시지 내용은 저장소에 넣지 마세요. `build/`와 로컬 설정은 버전 관리하지 않습니다.
