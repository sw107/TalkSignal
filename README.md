# TalkSignal

지정한 카카오톡 채팅방에 안 읽은 메시지가 있으면 macOS 메뉴바에 표시하는 개인용 앱입니다. 0.3은 카카오톡 자체 로컬 DB에서 개인 이름과 채팅방 이름을 찾아 안 읽은 수를 읽습니다. 카톡이 실행 중이라면 **카톡 창과 알림 센터를 모두 닫아도** 조회할 수 있습니다.

## Windows 준비판

`Windows/`는 Windows 11 x64를 대상으로 한 별도 .NET 트레이 앱입니다. **실제 카카오톡 안 읽음 감지 연동은 아직 구현되지 않았습니다.** 트레이·설정·자동 실행·표시 체험 및 이미 열린 대상 대화창 선택 기능을 제공합니다. Mac 앱/권한/빌드에는 영향을 주지 않습니다.

GitHub Actions의 `windows-2025` 가상머신에서 빌드·실행 검사를 수행하고 런타임을 포함한 ZIP을 만듭니다. 맥에 Windows/VM/.NET을 설치하지 않습니다. Windows Server VM 결과는 Windows 11의 실제 카톡 계정·폰 읽음 동기화 검증과 다릅니다. 실행과 제거 방법은 [Windows/README.txt](Windows/README.txt), 검증 범위는 [Windows/TESTING.md](Windows/TESTING.md)를 참고하세요.

## 사용 방법

1. `build/TalkSignal.app`을 실행하고 메뉴바 아이콘 **우클릭 → 설정…**을 엽니다.
2. **개인 이름 또는 채팅방 이름**을 띄어쓰기·이모지까지 입력하고 아이콘과 숫자 표시 여부를 선택합니다. **저장하고 적용**을 누릅니다. 개인 이름은 그 사람과의 1:1 채팅, 단체방 이름은 그 방 전체의 안 읽은 수를 확인합니다. 단체방 안에서 특정 사람이 보낸 것만 고르는 기능은 아닙니다.
3. **시스템 설정 → 개인정보 보호 및 보안 → 전체 디스크 접근**에서 **TalkSignal**을 허용합니다. 목록에 없으면 `+`로 이 앱을 추가합니다. macOS 안내가 나오면 **종료 및 다시 열기**를 누릅니다. 진단용 Unread Check의 권한과는 별개입니다.
4. 카카오톡은 로그인한 채 실행해 둡니다. 빨간 버튼으로 창을 닫아도 됩니다. 앱 자체를 종료하면 감지할 수 없습니다.

| 표시 | 의미 |
| --- | --- |
| 선택한 아이콘 + 분홍색 점 및 선택적 숫자 | 지정한 채팅방에 안 읽은 메시지가 있음 |
| 선택한 아이콘만 표시, 상태가 ‘안 읽은 메시지가 없어요’ | 조회 성공, 안 읽은 수 0 |
| 선택한 아이콘 + 주황색 점 | 권한 부족, 카톡 종료, 이름 미발견·중복, DB 조회 실패 등 |

폰에서 읽은 상태가 Mac의 카톡 DB에 동기화되면 다음 조회에서 분홍색 점과 숫자가 꺼집니다. 기본 아이콘은 설정 메뉴를 열 수 있도록 남습니다. 기본 조회 간격은 3초이며 네트워크 동기화·절전·첫 실행 준비 시간에 따라 반영이 늦어질 수 있습니다. 준비 중에는 메뉴에 진행 상태를 표시합니다.

**메뉴바 아이콘 클릭**은 설정한 이름을 DB에서 다시 확인한 뒤 카카오톡 채팅 목록에서 정확히 일치하는 방을 선택해 엽니다. 이 동작에는 TalkSignal의 **손쉬운 사용 권한**이 추가로 필요합니다. 이름이 중복되거나 조회·화면 확인에 실패하면 다른 방을 추측해서 열지 않습니다. **우클릭 또는 Control-클릭**은 설정·지금 확인·종료 메뉴를 엽니다. 설정 창의 **저장된 대상 채팅방 열기**도 같은 동작이며, **카카오톡 열기** 메뉴는 기존처럼 카톡 앱만 엽니다. 메시지를 보내는 기능은 없습니다.

**지금 확인**은 즉시 다시 조회하고 중단된 계정 탐색을 재시도합니다. **알림 표시 미리보기**는 4초간 분홍색 점의 모양만 보여 주며 실제 메시지나 읽음 상태를 변경하지 않습니다.

## 권한과 개인정보

**요구하는 macOS 권한은 실제로 ‘전체 디스크 접근’입니다. 카톡 폴더만 허용하는 권한이 아닙니다.** 아래의 접근 범위는 현재 앱 코드의 동작이며, macOS가 카톡 폴더만 접근하도록 제한해 주는 샌드박스는 아닙니다.

- 카톡 컨테이너의 로컬 DB와 카톡 설정 파일, 이 Mac의 기기 식별값을 사용합니다. 다른 문서·사진·메일을 탐색하는 기능은 없습니다.
- DB는 `SQLITE_OPEN_READONLY`와 `query_only`로 엽니다. SQL 읽기 허용 열은 방 이름·안 읽은 수·이름 연결 ID와 개인 이름, 방 제목 메타데이터, 오픈채팅 이름, 이름 없는 단체방의 표시 이름을 구성하는 참여자 ID입니다. `NTChatMeta.content`는 고정 SELECT에서 `type=3`인 **방 제목**만 읽습니다. 메시지 테이블·본문·첨부파일·전화번호 조회 및 DB 변경은 허용하지 않습니다.
- 기본 방 이름 → 별도 방 제목 → 오픈채팅 이름 → 1:1 상대 이름 → 참여자 이름을 조합한 단체방 이름 순서로 표시 이름을 정합니다. 이름을 바꾼 1:1 방은 현재 상대 이름으로도 찾을 수 있습니다. 단체방 참여자 한 사람의 이름만으로 그 방을 선택하지 않습니다.
- 앞뒤 공백과 한글 정규화를 제외하면 완전 일치로 찾습니다. 같은 방이 여러 이름에 해당하더라도 한 번만 집계하며, 서로 다른 방이 같은 이름이면 감지를 중단합니다. NULL·조회 실패는 0으로 간주하지 않습니다.
- 첫 실행 시 로컬 계정 식별값을 확인하고 DB 키를 메모리에서 계산합니다. 필요하면 제한된 범위에서 로컬 해시 비교를 수행하므로 처음 수십 초간 CPU 사용량이 늘 수 있습니다. 탐색은 회당 90초, 최대 3회로 제한합니다. 키·계정 식별값을 파일이나 명령행 인자로 저장하지 않습니다.
- 감지 이름·아이콘·숫자 표시 설정만 UserDefaults에 저장합니다. 메인 앱은 메시지 본문이나 수신 기록을 저장하지 않으며 네트워크 요청·분석 SDK·외부 전송 기능이 없습니다. 별도 진단 앱의 보고서는 메인 앱에 포함하지 않습니다.
- 자동 감지와 TalkSignal 자동 실행은 카카오톡을 열거나 조작하지 않습니다. 사용자가 메뉴바 아이콘을 클릭한 경우에만 카카오톡을 엽니다. 채팅방이 열리면 카카오톡 자체 동작으로 읽음 처리될 수 있습니다. 클릭 시 손쉬운 사용 API로 창 제목·목록의 방 이름·검색란·선택 상태만 확인합니다. 대화 내용과 미리보기 영역을 탐색하지 않으며, 클립보드를 사용하지 않습니다. 입력은 확인한 카톡 프로세스로만 보내며, 검색란·목록의 초점을 확인합니다. Enter는 정확한 대상 한 행이 선택되고 목록에 초점이 있을 때만 전달합니다. 자동 감지에는 손쉬운 사용 권한이 필요하지 않습니다.

## 자동 실행과 제약

- 이 Mac의 기존 **로그인 시 열기** 등록과 앱 경로를 유지하도록 업데이트합니다. 다른 Mac에서는 **시스템 설정 → 일반 → 로그인 항목 및 확장 프로그램**에 앱을 추가하세요. 카카오톡도 실행·로그인되어 있어야 합니다.
- 비공식 DB 구조를 이용합니다. 카카오톡 업데이트나 계정 변경에 따라 동작하지 않을 수 있습니다. 실행 PID·계정 표식이 바뀌면 캐시를 버립니다. 여러 계정이 감지되면 추측해서 표시하지 않습니다. 로그아웃·다중 계정 전환의 실제 검증은 아직 하지 않았습니다.
- 단체방의 별도 제목 저장 위치와 이름 없는 방의 참여자 이름 조합을 지원합니다. 카톡 버전·방 종류에 따라 실제 표시 이름과 달라질 수 있으며, 호환성을 확인하지 못하면 다른 방을 추측해 선택하지 않습니다. 실제 검증 범위는 `TESTING.md`를 참고하세요.
- 절전·로그아웃 중 실시간 감지는 불가능합니다. 폰의 읽음 상태를 Mac의 카톡이 아직 동기화하지 않았다면 잠시 기존 숫자가 남을 수 있습니다.
- 공식 Kakao API가 아니며 Kakao와 무관한 개인 프로젝트입니다. Developer ID 서명·공증 없이 로컬 ad-hoc 서명합니다. 재빌드하면 전체 디스크 접근 권한을 다시 등록해야 할 수 있습니다.

## 빌드와 테스트

현재 빌드는 Apple Silicon macOS 27 이상, Xcode Command Line Tools, Homebrew `sqlcipher` 및 `openssl@4`를 사용합니다. SQLCipher와 libcrypto를 앱 안에 복사하므로 배포 앱은 Homebrew의 라이브러리 경로에 의존하지 않습니다. 관련 라이선스도 앱 리소스에 포함합니다.

```sh
./scripts/test.sh
./scripts/build.sh
```

빌드 결과는 `build/staging/TalkSignal.app`입니다. 실행 중인 TalkSignal을 종료한 다음 기존 `build/TalkSignal.app`을 백업하고 결과를 그 경로로 복사합니다. 기존 설정·로그인 항목을 유지하려면 앱 경로와 번들 ID를 바꾸지 마세요. 테스트는 가상 DB를 사용하며 실제 카톡 DB를 수정하지 않습니다.

## 구조

- `Sources/App.swift`: 메뉴바·설정·조회 스케줄
- `Sources/ChatOpener.swift`: 명시적 클릭 시 접근성으로 채팅 목록에서 방 열기
- `Sources/ChatReader.swift`: 실행 상태·조회 오류·중복 이름 처리
- `Sources/Database/`: 공유 읽기 전용 DB 리더, 이름 해석, 메모리 내 키 계산
- `Tests/CoreTests.swift`, `Diagnostics/Unread/SelfTests.swift`: 이름·표시 상태·SQL 접근 제한 검사
- `Diagnostics/`: 별도 실험용 앱. 메인 앱은 알림 센터 DB나 접근성 기반 감지를 사용하지 않음

개인 이름이나 메시지 내용은 저장소에 넣지 마세요. `build/`와 로컬 설정은 버전 관리하지 않습니다.

## 이름 저장 구조 참고

별도 방 제목(`NTChatMeta`의 type 3), 오픈채팅 이름, 참여자 이름 조합의 저장 구조는 [kakaocli 이름 해석 구현](https://github.com/Jaeha0526/kakaocli/blob/2c74e63d2c8846c50d8eb1895eb6d835bfef4bc9/Sources/KakaoCore/Database/DatabaseReader.swift)을 참고했습니다. TalkSignal은 메시지·첨부파일 조회 및 네트워크 기능을 가져오지 않고 이름 조회만 고정 SQL과 허용 열 목록으로 구현합니다.
