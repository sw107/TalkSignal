# TalkSignal

지정한 카카오톡 채팅방에 안 읽은 메시지가 있으면 macOS 메뉴바에 표시하는 개인용 앱입니다. 0.4는 App Sandbox 안에서 카카오톡 자체 로컬 DB에서 개인 이름과 채팅방 이름을 찾아 안 읽은 수를 읽습니다. 카톡이 실행 중이라면 **카톡 창과 알림 센터를 모두 닫아도** 조회할 수 있습니다.

## Windows 준비판

Windows 작업은 중단한 상태입니다. `Windows/`는 Windows 11 x64를 대상으로 한 별도 .NET 트레이 앱입니다. **실제 카카오톡 안 읽음 감지 연동은 아직 구현되지 않았습니다.** 트레이·설정·자동 실행·표시 체험 및 이미 열린 대상 대화창 선택 기능을 제공합니다. Mac 앱/권한/빌드에는 영향을 주지 않습니다.

GitHub Actions의 `windows-2025` 가상머신에서 빌드·실행 검사를 수행하고 런타임을 포함한 ZIP을 만듭니다. 맥에 Windows/VM/.NET을 설치하지 않습니다. Windows Server VM 결과는 Windows 11의 실제 카톡 계정·폰 읽음 동기화 검증과 다릅니다. 실행과 제거 방법은 [Windows/README.txt](Windows/README.txt), 검증 범위는 [Windows/TESTING.md](Windows/TESTING.md)를 참고하세요.

## 사용 방법

1. `build/TalkSignal.app`을 실행하고 메뉴바 아이콘을 클릭해 설정을 엽니다.
2. **개인 이름 또는 채팅방 이름**을 띄어쓰기·이모지까지 입력하고 아이콘과 숫자 표시 여부를 선택합니다. **저장하고 적용**을 누릅니다. 개인 이름은 그 사람과의 1:1 채팅, 단체방 이름은 그 방 전체의 안 읽은 수를 확인합니다. 단체방 안에서 특정 사람이 보낸 것만 고르는 기능은 아닙니다.
3. **카톡 폴더 읽기 전용 연결…**을 눌러 안내된 카톡 설정 폴더와 DB 폴더를 각각 선택합니다. 다른 폴더나 상위 폴더는 받지 않습니다. 전체 디스크 접근·손쉬운 사용을 요구하는 이전 방식은 제거했습니다. 기존 TalkSignal 및 더 이상 쓰지 않는 진단 앱의 해당 권한은 시스템 설정에서 해제하세요. 선택한 폴더만으로 실제 조회되는지 검증 범위는 `TESTING.md`에 기록합니다.
4. 카카오톡은 로그인한 채 실행해 둡니다. 빨간 버튼으로 창을 닫아도 됩니다. 앱 자체를 종료하면 감지할 수 없습니다.

| 표시 | 의미 |
| --- | --- |
| 선택한 아이콘 + 분홍색 점 및 선택적 숫자 | 지정한 채팅방에 안 읽은 메시지가 있음 |
| 선택한 아이콘만 표시, 상태가 ‘안 읽은 메시지가 없어요’ | 조회 성공, 안 읽은 수 0 |
| 선택한 아이콘 + 주황색 점 | 권한 부족, 카톡 종료, 이름 미발견·중복, DB 조회 실패 등 |

폰에서 읽은 상태가 Mac의 카톡 DB에 동기화되면 다음 조회에서 분홍색 점과 숫자가 꺼집니다. 기본 아이콘은 설정 메뉴를 열 수 있도록 남습니다. 기본 확인 간격은 5초(타이머 여유 1초)이며 네트워크 동기화·절전·첫 실행 준비 시간에 따라 반영이 늦어질 수 있습니다. 준비 중에는 메뉴에 진행 상태를 표시합니다.

**메뉴바 아이콘 클릭**은 TalkSignal 설정을 엽니다. **우클릭 또는 Control-클릭**은 설정·지금 확인·종료 메뉴를 엽니다. 카카오톡이나 채팅방을 열고 조작하는 기능은 제거했습니다.

**지금 확인**은 즉시 다시 조회하고 중단된 계정 탐색을 재시도합니다. **알림 표시 미리보기**는 4초간 분홍색 점의 모양만 보여 주며 실제 메시지나 읽음 상태를 변경하지 않습니다.

## 권한과 개인정보

App Sandbox를 활성화하고 사용자 선택 파일의 읽기 전용 권한과 앱 범위 보안 북마크만 서명에 포함합니다. 네트워크 client/server, 파일 쓰기, 임시 파일 접근 예외, 손쉬운 사용·Apple Events 권한은 추가하지 않습니다. OS가 선택하지 않은 개인 파일과 직접 네트워크 연결을 제한합니다. 앱 자체 컨테이너와 OS가 기본 허용하는 시스템 자원까지 모두 차단한다는 의미는 아닙니다.

- 허용 대상은 `~/Library/Containers/com.kakao.KakaoTalkMac/Data/Library/Preferences`와 그 `Library/Application Support/com.kakao.KakaoTalkMac` 폴더입니다. 계정별 설정 파일과 DB의 WAL/SHM 파일 때문에 폴더 단위 읽기 권한을 받습니다. 선택 폴더 안의 모든 파일에 대한 읽기 권한이 생기며, 코드에서는 이름이 일치하는 카톡 plist와 정해진 DB 이름만 엽니다. 다른 위치로 향하는 심볼릭 링크는 거부합니다.
- 기기 식별값(IOPlatformUUID)과 카톡 설정에서 추출한 계정 식별값으로 DB 키를 계산합니다. 다른 프로세스의 메모리를 열거나 검색하지 않습니다. 설정 plist는 파싱할 때 전체 파일이 메모리에 들어오며 DB도 페이지 단위로 읽으므로, 방 이름과 숫자에 해당하는 바이트만 읽는다고 보장하지 않습니다.
- DB는 `SQLITE_OPEN_READONLY`와 `query_only`로 엽니다. 읽기 전용 연결을 재사용해 매번 암호화 키를 적용하는 비용을 줄이고, `PRAGMA data_version`이 바뀌거나 감지 대상이 바뀐 경우에만 방을 재조회합니다. 대기 중 읽기 트랜잭션은 유지하지 않습니다. 계정/PID/DB 파일 교체 또는 오류 시 연결·캐시를 버립니다. 설정 파일은 inode·크기·수정/변경 시각을 확인해 바뀔 때만 다시 파싱하며, 폴더 북마크의 URL 해석은 메모리에서 재사용합니다. 매 조회 때 정확한 허용 경로를 검증하고 읽기 전용 보안 범위를 열고 닫습니다. 이름 탐색 후 하나의 방이 확정되었을 때만 그 방의 안 읽은 수를 바인딩한 ID로 조회합니다. 읽기 트랜잭션으로 두 조회 사이의 일관성을 유지합니다. 테이블·열 제한은 SQL authorizer와 고정 쿼리로 적용하며 OS의 열 단위 차단은 아닙니다. SQL 읽기 허용 열은 방 이름·안 읽은 수·이름 연결 ID와 개인 이름, 방 제목 메타데이터, 오픈채팅 이름, 이름 없는 단체방의 표시 이름을 구성하는 참여자 ID입니다. `NTChatMeta.content`는 고정 SELECT에서 `type=3`인 **방 제목**만 읽습니다. 메시지 테이블·본문·첨부파일·전화번호 조회 및 DB 변경은 허용하지 않습니다.
- 기본 방 이름 → 별도 방 제목 → 오픈채팅 이름 → 1:1 상대 이름 → 참여자 이름을 조합한 단체방 이름 순서로 표시 이름을 정합니다. 이름을 바꾼 1:1 방은 현재 상대 이름으로도 찾을 수 있습니다. 단체방 참여자 한 사람의 이름만으로 그 방을 선택하지 않습니다.
- 앞뒤 공백과 한글 정규화를 제외하면 완전 일치로 찾습니다. 같은 방이 여러 이름에 해당하더라도 한 번만 집계하며, 서로 다른 방이 같은 이름이면 감지를 중단합니다. NULL·조회 실패는 0으로 간주하지 않습니다.
- 첫 실행 시 로컬 계정 식별값을 확인하고 DB 키를 메모리에서 계산합니다. 필요하면 제한된 범위에서 로컬 해시 비교를 수행하므로 초기 준비 동안 CPU 사용량이 늘 수 있습니다. 탐색은 한 작업 스레드에서 작은 구간별로 쉬어 가며 수행하고 회당 90초, 최대 3회로 제한합니다. 초기 준비 시간이 길어질 수 있으나 동시에 4개 코어를 사용하던 동작을 제거했습니다. 키·계정 식별값을 파일이나 명령행 인자로 저장하지 않습니다.
- 감지 이름·아이콘·숫자 표시 설정과 선택 폴더의 보안 북마크를 앱의 UserDefaults에 저장합니다. 메인 앱은 메시지 본문이나 수신 기록을 저장하지 않으며 네트워크 요청·분석 SDK·외부 전송 기능이 없습니다. 별도 진단 앱의 보고서는 메인 앱에 포함하지 않습니다.
- 자동 감지·아이콘 클릭·자동 실행 어느 경로에서도 카카오톡을 열거나 조작하지 않습니다. 손쉬운 사용, 키보드 입력 전송, 클립보드 기능은 메인 앱에서 제거했습니다.

## 자동 실행과 제약

- 이 Mac의 기존 **로그인 시 열기** 등록과 앱 경로를 유지하도록 업데이트합니다. 다른 Mac에서는 **시스템 설정 → 일반 → 로그인 항목 및 확장 프로그램**에 앱을 추가하세요. 카카오톡도 실행·로그인되어 있어야 합니다.
- 비공식 DB 구조를 이용합니다. 카카오톡 업데이트나 계정 변경에 따라 동작하지 않을 수 있습니다. 실행 PID·계정 표식이 바뀌면 캐시를 버립니다. 여러 계정이 감지되면 추측해서 표시하지 않습니다. 로그아웃·다중 계정 전환의 실제 검증은 아직 하지 않았습니다.
- 단체방의 별도 제목 저장 위치와 이름 없는 방의 참여자 이름 조합을 지원합니다. 카톡 버전·방 종류에 따라 실제 표시 이름과 달라질 수 있으며, 호환성을 확인하지 못하면 다른 방을 추측해 선택하지 않습니다. 실제 검증 범위는 `TESTING.md`를 참고하세요.
- 절전·로그아웃 중 실시간 감지는 불가능합니다. 폰의 읽음 상태를 Mac의 카톡이 아직 동기화하지 않았다면 잠시 기존 숫자가 남을 수 있습니다.
- 공식 Kakao API가 아니며 Kakao와 무관한 개인 프로젝트입니다. Developer ID 서명·공증 없이 로컬 ad-hoc 서명합니다. 서명·앱 위치가 바뀌면 보안 북마크를 다시 연결해야 할 수 있습니다.

## 빌드와 테스트

현재 빌드는 Apple Silicon macOS 27 이상, Xcode Command Line Tools, Homebrew `sqlcipher` 및 `openssl@4`를 사용합니다. SQLCipher와 libcrypto를 앱 안에 복사하므로 배포 앱은 Homebrew의 라이브러리 경로에 의존하지 않습니다. 관련 라이선스도 앱 리소스에 포함합니다.

```sh
./scripts/test.sh
./scripts/build.sh
./scripts/test-sandbox.sh
```

빌드 결과는 `build/staging/TalkSignal.app`입니다. 실행 중인 TalkSignal을 종료한 다음 기존 `build/TalkSignal.app`을 백업하고 결과를 그 경로로 복사합니다. 기존 설정·로그인 항목을 유지하려면 앱 경로와 번들 ID를 바꾸지 마세요. DB 테스트는 가상 데이터를 사용하며 실제 카톡 DB를 수정하지 않습니다. 샌드박스 검사는 별도 검사 앱에 본 앱과 동일한 entitlement를 적용해 합성 파일의 읽기·쓰기와 로컬 네트워크 연결이 거부되는지 확인합니다. 실제 폴더 선택·북마크 재시작·카톡 수신 및 폰 읽음 동기화 검증을 대체하지 않습니다.

## 구조

- `Sources/App.swift`: 메뉴바·설정·조회 스케줄
- `Sources/Database/FileAccess.swift`: 지정된 두 폴더의 읽기 전용 북마크와 접근 수명 관리
- `Resources/TalkSignal.entitlements`: App Sandbox 권한 목록
- `Sources/ChatReader.swift`: 실행 상태·조회 오류·중복 이름 처리
- `Sources/Database/`: 공유 읽기 전용 DB 리더, 이름 해석, 메모리 내 키 계산
- `Tests/CoreTests.swift`, `Diagnostics/Unread/SelfTests.swift`: 이름·표시 상태·SQL 접근 제한 검사
- `Diagnostics/`: 별도 실험용 앱. 메인 앱은 알림 센터 DB나 접근성 기반 감지를 사용하지 않음

개인 이름이나 메시지 내용은 저장소에 넣지 마세요. `build/`와 로컬 설정은 버전 관리하지 않습니다.

## 이름 저장 구조 참고

별도 방 제목(`NTChatMeta`의 type 3), 오픈채팅 이름, 참여자 이름 조합의 저장 구조는 [kakaocli 이름 해석 구현](https://github.com/Jaeha0526/kakaocli/blob/2c74e63d2c8846c50d8eb1895eb6d835bfef4bc9/Sources/KakaoCore/Database/DatabaseReader.swift)을 참고했습니다. TalkSignal은 메시지·첨부파일 조회 및 네트워크 기능을 가져오지 않고 이름 조회만 고정 SQL과 허용 열 목록으로 구현합니다.
